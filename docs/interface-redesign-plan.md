# PartnerLedger 整体界面改版执行计划

编写日期为 2026-11-19。基线提交为 9ffdfc3，包含正式三端项目、商机与拜访同步，以及表格查找替换。本轮交付为设计分析和实施计划，页面开发按下列顺序开展。

## 1. Azure 源码观察与项目方向

通过 browser-cdp 查看 Azure 中文官网，并直接读取 DOM、计算样式和网站加载的 CSS。观察时浏览器布局视口为 968 × 682 CSS 像素。截图受设备缩放影响，以下字号来自计算样式及 CSS 声明。

- 首屏为深色背景，文字与按钮对比清楚。下方使用浅蓝底、白色卡片和分段导航，区域之间有充分留白。当前首页正在展示 Ignite 主题，主视觉含多色光线，属于当期营销内容。
- 实测首屏标题 44px、行高 56px、字重 500。分区标题 40px／48px，卡片标题 24px／32px。正文 16px／24px，按钮 15px／22px。
- 字体使用 Segoe UI Variable Display / Text，并提供 Segoe UI 与系统无衬线回退。主题 CSS 另外定义了正文大号 18px／28px、小号 14px／20px、辅助字号 12px／16px。
- 官网常用蓝色为 #0078D4，深色文字可见 #0E1726、#17253D，浅底可见 #F4FAFD。正文色、按钮色、状态色分别承担不同含义。
- 内容卡片实测圆角 24px，白底、轻阴影。按钮因组件位置而异，实测存在 3px 和 8px 圆角。首屏两列布局的横向间隔为 16px，容器在该视口左右各留 56px。
- deferred CSS 定义了容器变量 1328px，以及 540px、860px、1440px 断点。critical CSS 用设计变量管理字号、行高和主题色，组件按页面语义组合。

项目采用蓝色企业软件视觉。公开门户负责介绍渠道协作价值，三端工作台负责办理业务。原创视觉以客户、代理商、厂商的三条协作路径汇入同一项目为主题，沿用渠智链品牌与图标，绘制自己的构图与交互。

参考来源包括 [Azure 中文官网](https://azure.microsoft.com/zh-cn)、[critical 主题 CSS](https://azure.microsoft.com/acom/etc.clientlibs/cascade.component.authoring/clientlibs/clientlib-reimagineui/foundation/themes/critical.ACSHASH79a24d2ef5ac0ab16d96f21e5ae89510.min.css)、[deferred 布局 CSS](https://azure.microsoft.com/acom/etc.clientlibs/cascade.component.authoring/clientlibs/clientlib-reimagineui/foundation/themes/deferred.ACSHASHb750f374bfd6defbaa65dd6d8c58cd41.min.css)。哈希文件路径对应本次访问版本。

## 2. 先建立统一视觉规范

先更新 frontend/src/ui/theme.css 和 /ui 组件预览页，再迁移实际页面。沿用现有 --ui-* 变量名与 UiButton、UiCard、UiBadge 等组件入口，页面局部颜色统一引用语义变量。

### 颜色

- 主色 --ui-accent 使用 #0078D4，悬停 #0067B8，浅底 #EAF4FC，描边 #BDDDF3。焦点使用 #005A9E，并提供 2px 可见轮廓。
- 页面底色 #F4F8FC，卡片底色 #FFFFFF，次级区域 #F8FAFD，普通分隔线 #D7E2EC，表单边框 #7C8D9F。
- 主要文字 #17253D，正文 #35485F，辅助文字 #526579。深蓝区域使用 #102A43 至 #163D61 的轻渐变，配浅白文字。
- 成功使用 #0F6B48 / #EAF6EF，警告使用 #805600 / #FFF4D6，错误使用 #B42318 / #FDEDEC，普通提示沿用蓝色。
- 蓝色表示可操作或已选中。状态必须同时包含文字，关键状态附图标。角色使用客户、代理商、厂商的名称与图标识别。
- 复核正文对比度至少 4.5:1，大字及必要控件边界至少 3:1。渐变区、禁用项、选中项和表格高亮分别检查。

### 字体、空间和组件

- 字体栈优先 Segoe UI Variable、Segoe UI、Microsoft YaHei UI、PingFang SC、系统无衬线。使用本机字体回退，中文不压缩字距。数字金额采用等宽数字特性，编号及公式使用等宽字体。
- 门户主标题手机 32px／40px，中屏 44px／56px，1440px 起 56px／64px。门户分区标题大屏 40px／48px，手机 28px／36px。门户正文 16px／26px，说明主文可用 18px／28px。
- 工作台页标题 32px／40px，手机 26px／34px。卡片标题 18px／26px，正文 14px／22px。表格正文与关键状态 14px／22px，次要编号 12px／18px。
- 普通控件高 40px，紧凑操作 32px，手机触控目标至少 44px，手机输入文字 16px。主要按钮采用 6px 圆角，普通卡片 12px，门户大卡片 20px，标签可保留胶囊形。
- 空间使用 4、8、12、16、24、32、48、64、96px。卡片正文内边距默认 24px，紧凑业务区域 16px，手机 16px。
- 白色卡片只使用轻描边和轻阴影。悬停改变边框或浅底，位移最多 2px。过渡 120–180ms，并尊重 prefers-reduced-motion。
- 同步 Element Plus 对话框、遮罩、校验、按钮及输入框样式。HTML 原生表单、弹窗和表格组件也须适配。

## 3. 页面布局与三端协作

### 门户与三个登录入口

- 门户采用白色导航、深蓝首屏、浅蓝内容区。首屏左侧标题和价值介绍，右侧为原创三方协作示意，以需求、报价、交付的关系表达业务。
- 三个入口并列展示，各自写清主要任务。代理商作为重点入口，厂商与客户使用相同组件结构，入口都能直接进入已有登录流程。
- 首屏之后依次展示三方协作过程、商机拾遗实例、继续体验入口和页脚。商机实例明确标注样例来源。
- 点击协作阶段时，切换该角色的任务和可见信息示意。首屏视觉采用原创素材，图片需提供合适尺寸、替代说明和加载占位。
- 登录页采用浅蓝背景与白色登录面板，保留角色名称、账号输入、错误信息、回首页和演示入口。桌面两列，手机单列。
- 门户内容净宽上限 1328px，左右留白使用 clamp(20px,4vw,56px)。540px 以下入口卡片纵排，首屏示意移到文案下方。

### 共用工作台外壳

- WorkspaceShell 采用 56px 顶栏、232px 左侧导航和浅蓝灰主区域。顶栏显示品牌、当前组织、角色与账号入口，主区显示面包屑和当前业务操作。
- 导航选中项使用浅蓝底、蓝色图标与左侧短标记。图标与标题共同识别页面，正式环境与演示环境各有清楚的文字标识。
- 860px 以下导航收为可开关抽屉。关闭后焦点回到触发按钮，抽屉支持 Escape、焦点约束与当前页面标记。手机顶栏保留组织、角色与菜单的必要入口。
- 统计卡放在任务区上方，每张可操作卡片进入对应已有筛选。工作台主内容上限 1440px，表格工作区可充分使用宽度。

### 三端项目页面

- 代理商首页优先展示待报价、待厂商回复、待客户补充和商机跟进。厂商首页优先显示询价队列与能力缺口办理。客户首页优先显示采购项目、待答复问题和已有进度。
- 项目详情统一为项目标题与编号、当前状态和办理操作、业务资料、报价或交付明细、事件时间线。桌面主资料与时间线两列，手机单列。
- 增加可复用的协作进度组件。已有业务状态决定当前阶段，当前角色的 actions 决定可办理事项。缺少可靠信息时使用“等待协作方回复”等现有状态文案。
- 厂商渠道报价与对客报价使用相同的阅读结构，清楚展示类型、版本、有效期、明细与合计。报价历史提供版本标识和已有差异说明。
- 询价摘要、客户原始需求、代理商内部信息按服务端已返回的字段展示。流程图和时间线也遵循相同可见范围。跨端回归用同一项目编号验证。
- 正式接口已开放的项目和商机展示真实记录。尚在演示中的报价、订单与验收继续带演示标识。

### 商机、拜访、产品与 AI 页面

- 商机首页采用“今天接着办 + 可筛选台账”。待办由现有 tasks 中的原因、项目和动作组成。新匹配提醒使用浅蓝或青蓝强调，并展示对应证据入口。
- 商机详情把需求、合作依据、联系前核对和引荐记录分区。费用与跟进日期使用业务明细样式。核对清单的可行、待确认和有问题分别有文字及状态提示。
- 记拜访保持手机优先，正文输入、关联项目、保存与核对操作按顺序排列。已同步草稿、待核对提交、本机待同步记录各有清楚标题及操作。
- 产品目录使用白色产品卡与紧凑筛选栏，厂家发布和代理商查看都沿用既有权限。产品详情以模块、版本和部署信息为主要层次。
- AI 需求解析使用输入区、可编辑结果区、人工确认区。员工数和授权数分别展示，未知字段留空，失败提示旁保留手工入口。

### 表格工作台及旧原型

- /tables 的颜色、字体、页头、表格列表、工具栏和弹窗接入同一套变量。局部 --grid-* 变量映射到 --ui-*，保持表格相关样式的独立作用域。
- 活动单元格使用蓝色边框，选区使用浅蓝填充。查找命中、当前命中、待保存、保存失败分别有可辨认的边框或图标与文字。
- 带回最新 GridSearch 的查找替换面板、替换预览、冲突与失败反馈。公式栏、行列标题、批量选择和保存状态均纳入改版验收。
- /demo 旧双角色原型及 /experience 三端演示跟随共用设计规范，保留原有入口和样例重置能力。

## 4. 按阶段交付

1. **组件样板**。修改主题变量和共用 UI 组件，在 /ui 展示按钮、卡片、字段、状态、表格行和弹窗的完整状态。整理 portal、channel、live、tables 内写死的颜色为语义变量。通过视觉检查后作为全站基线。
2. **门户和登录**。完成首页、三个登录入口和原创三方协作示意。检查 375、860、1440px 下的布局与文字换行，实测所有正式及演示入口。
3. **外壳及项目**。迁移共用外壳、三端首页、列表、详情、询价与补资料表单。以客户建项、代理商询价、厂商反馈、客户答复的同一笔记录进行回归。
4. **商机和拜访**。迁移正式与演示商机、伙伴、核对清单、引荐动作、草稿同步与待确认提交页面。覆盖新伙伴唤回、分别已读、旧草稿同步和手机续写。
5. **表格和旧页面**。迁移 /tables 的查找替换、编辑及冲突样式，完成 AI、目录和旧原型的剩余覆盖。检查弹窗、空数据、加载、访问失败、会话失效等状态。
6. **验收及交接**。统一视觉走查、业务回归、截图对比并更新组件说明及演示脚本。每阶段提交聚焦对应页面，验证后按项目约定推送，交接中注明已迁移范围。

前端和产品实现由 wweijie473-boop 负责。本次视觉方案复用现有 API、组件属性、动作、请求键和版本检查。若呈现所需信息在响应中缺失，先使用已知状态文案，并在交接中列出字段需求供 mayisuix 确认。

## 5. 完成标准

- 覆盖 /、三个 /login 入口、三个 /experience 入口、/ui、/tables、/demo 及其弹窗与错误状态。工作台中途页面和恢复提交界面都有明确样式。
- 在 375、540、860、1440、1920px 检查。页面主体无非预期横向滚动，宽表格在自己的区域内滚动。手机输入与保存操作触达舒适，标题和金额完整可读。
- 键盘可操作导航、筛选、表单、弹窗及表格。焦点可见、错误可读，状态含文字，中文、长项目名称和大金额不会挤坏布局。
- 正式三端完成建项、询价、补资料、缺口反馈的联调。检查客户看不到渠道内部信息，厂商看不到客户原始自由文本。商机按组织共享、草稿按成员隔离，分别已读及主单关联继续有效。
- 回归草稿同步、重复确认、响应丢失后的原请求重放、版本冲突后的重新核对。页面反馈与实际保存结果一致。
- 表格完成坐标跳转、选区、输入、公式、粘贴、撤销、查找、替换、自动保存、请求重放和冲突处理回归，检查只读账号。
- 运行 npm test 与 npm run build。使用独立测试环境和虚构数据做写入验证。截图交付至少包含门户、三个工作台、项目详情、商机匹配、手机拜访和表格查找替换。
- 验收记录注明正式与演示能力、视口尺寸、实际检查结果和待处理问题。最终回看主色、文字层级、控件尺寸、间距与业务状态的全站一致性。
