# 三端协作与商机拾遗演示

本脚本使用虚构组织、产品和合作记录。前端运行后，在同一浏览器、同一地址的三个标签分别打开客户、代理商、厂商演示。用代理商页面底部「重置演示」恢复初始台账，该操作同时清理演示拜访草稿。

## 三至五分钟主线

1. 客户端 `/experience/customer` 提交“新基地 ERP 采购”，需求填写“20 席财务与库存，本地部署”。记下项目编号。切到代理商台账并打开同一编号，发起询价时只写必要的产品和实施范围。切到厂商前确认原始预算仅在客户与代理商之间可见。
2. 厂商打开刚收到的询价，可以要求补充部署资料，代理商再向客户提问。客户回复后，代理商核对并向厂商提交摘要。三方分别查看自己的时间线，指出客户没有上游私有事件，厂商没有原始客户自由文本。
3. 厂商标记“原厂暂不支持 ERP 至 MES 的工单对接服务”。代理商在同一项目的「主单之外的商机」中记录该缺口。让主询价继续出具渠道报价，代理商出具独立对客报价。客户确认、代理商下单后，厂商供货、代理商实施、客户验收。副需求保持独立，沿用原项目关联。
4. 代理商打开「记拜访」，选刚才的客户项目，输入“ERP 已定，客户还需要 ERP 对接 MES 的系统对接服务”。保存草稿，刷新，确认可继续整理。核对主采购事项与附加需求，点击「保存并记录附加商机」，在商机拾遗查看同一需求，再人工澄清类型为系统对接服务，源系统为 ERP，目标系统为 MES。
5. 展示已验收的 ERP → MES 示例合作依据和内部引荐人。打开「联系前核对」，分别登记软件版本、接口条件、实施地区、交付档期。若某项有问题，可登记未匹配原因，继续找其他伙伴。展示对外询问摘要，仅包含能力和系统类型。
6. 确认双方同意后登记引荐、约定介绍费、触发条件及跟进日期。登记已促成合作后，返回首页查看“合作已促成，需核对介绍费条件”的待办。实际收款核对后再手工登记结清。

## 补充场景与备用演示

- 模糊表达可填写“ERP 已定，客户还需要 IDE 接口”。核对时保留未知类型。商机详情会要求澄清成品连接器、定制对接还是插件，先向客户提问。
- 旧线索回访可新建 ERP → WMS 对接需求。初始没有相应伙伴。新增同能力、同系统的伙伴及经授权案例，返回工作总览，点击“新匹配到某团队，可以回访此需求”，查看依据。点击「已查看这批人选」后此条提醒消除。
- 客户约定答复可在待承接商机中选择「约定跟进日期」，事项选择客户答复，日期选择今天。首页可直接点这条理由回到详情。关闭商机后提醒消除。
- 不使用真实商业数字作为答辩成绩。演示时说明哪些结果是本地样例。录屏建议按上述顺序从头运行一次，保留项目编号和三个角色的操作画面。当前交付包含可执行脚本和可重置样例，录屏需在最终演示版本确认后制作。

## 正式接口联调

正式入口为 `/login/customer`、`/login/dealer`、`/login/vendor`，按后端启动说明准备 MySQL 迁移 000004、Redis、三个账号与组织关联。正式页面验收覆盖步骤 1、2 及步骤 3 的厂商缺口标记。报价、订单和验收仍在演示中体验。

正式代理商的「记拜访」页面使用真实可见项目并保存个人服务端草稿。原有本机记录由本人选择同步。核对并确认后生成团队可见的独立商机，点击「查看正式商机」办理。用同组织第二位成员验证商机共享与草稿原文隔离，候选已读状态分别保存。详见 [交班文档](opportunity-handoff.md) 中的 Issue #2 验收记录。
