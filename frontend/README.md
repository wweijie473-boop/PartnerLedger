# PartnerLedger Vue 前端

使用 Vue 3、Vite 和 Element Plus。在 PowerShell 中运行以下命令，然后打开终端显示的 `Local` 地址。

```powershell
Set-Location F:\PartnerLedger\frontend
npm ci
npm run dev
```

## 入口与体验

顶栏「搜索站内功能」查找公开功能和工作台入口，例如「工单」「资金总览」。登录后，同一搜索框还会查询组织可见的项目、订单、产品和工单。可输入名称或编号。业务结果点击后进入对应工作台记录，每类最多显示三条。

从首页顶部的「登录」进入 `/login`，再选择代理商、软件厂商或企业客户。也可以直接打开 `/login/dealer`、`/login/vendor` 或 `/login/customer`。入口与账号身份不符时会注销本次会话，并提示从对应入口登录。`/register` 用于注册所选身份的独立组织和首个账号。

无需启动后端即可访问 `/experience/dealer`、`/experience/vendor`、`/experience/customer`。每个角色有自己的待办和项目台账。打开详情后点击「切换身份」，下一个角色会进入同一项目；只有询价提交后，厂商才可看到项目。演示仅在同源浏览器之间共享本机样例，适合在同一浏览器的三个标签分别扮演三方。只使用虚构数据；「重置演示」会同时恢复三端样例。

从零体验：客户提交 ERP 采购需求 → 代理商核对字段并询价 → 厂商填写授权与实施明细 → 代理商独立编制对客报价 → 客户确认 → 代理商单独下单 → 厂商供货 → 代理商提交实施验收 → 客户确认或退回整改。也可从初始台账直接打开已经到达相应阶段的记录。

## 后端工作台

### 厂商直购与佣金

1. 厂商登录 `/login/vendor?view=pricing`，选择本组织已发布产品，设置直购价和佣金比例并开放订购。初始佣金建议值为 50%，按厂商保存的规则锁定每单的比例。
2. 代理商从「获取商机 → 推广获客二维码」发码。客户进入 `/retail-store` 的厂商商城，选择产品，登录企业客户账号后下单。代理商也可从「下单订购 → 代客下单」替关联客户创建订单，再把确认链接发给客户。链接打开对应订单，客户组织仍由服务端核验。
3. 客户按照厂商提供的方式完成站外付款。厂商在「直收订单与收款」核对并登记收款凭证后，订单佣金进入结算台账。
4. 代理商从「资金往来 → 佣金结算」查看待结、已结金额和催办记录。厂商从「代理商佣金结算」处理催办，完成转账后登记凭证。代理商可在同一台账查看结算结果。

### 厂商直购与佣金演示

运行 `npm run demo:retail` 并打开 `/experience/dealer`，体验推广、代客下单与佣金结算。使用手机扫码时，从终端显示的 `Network` 地址打开工作台。同一场演示共享三端订单。普通 `npm run dev` 启动正式联调和浏览器内的项目演示，直购和运营 SQLite 演示需使用 `retail-demo` 模式。

1. 在代理商中台进入「获取商机 → 推广获客二维码」，首次点击「开启演示」，再生成畅捷通演示厂商的二维码。可扫码或打开预览。同组的「商机拾遗」仍可处理原有商机。
2. 在厂商演示官网选购「云财务」并模拟付款。单份 ¥1,998.00 计入畅捷通的模拟收款，天津助飞企业咨询管理有限公司获得 ¥999.00 的待结佣金。
3. 在代理商中台进入「资金往来 → 佣金结算」，点击「催结算」。点击「切换到厂商后台」，在「直收订单与收款」核对收入，在「代理商佣金结算」查看催办并登记模拟转账凭证。点击「返回代理商中台」查看结算结果。
4. 在「下单订购 → 代客下单」选演示客户和产品，在「厂商直收订单」打开客户确认链接。客户确认并模拟付款后，沿用同一条收款、催办与结算流程。

手机和电脑连接同一网络时，从 Vite 输出的 `Network` 地址打开工作台再生成二维码。用 `localhost` 生成的码供电脑本机预览。演示订单、客户、购买链接和续费台账保存在本机 `frontend/var/retail-demo.sqlite`，需要 Node.js 22.13 或更新版本。同一浏览器和站点地址重进时会恢复同一场演示，服务重启后也会恢复。浏览器保存进入当前场次的凭证，项目演示仍保存在浏览器站点数据中。默认前端构建不包含此演示入口。

演示按畅捷通服务商专区的三处入口组织。其「获取商机」用云产品二维码和链接获取注册试用客户，「下单订购」区分服务商付款与客户付款，「资金往来」包含资金结算统计、服务费和推广费明细。演示采用客户直接付款、50% 样例佣金、按单催办和厂商登记转账。厂商后台是根据上述协作关系设计的 PartnerLedger 页面。 [获取商机](https://partner.chanjet.com/correct/#/business/index) · [下单订购](https://partner.chanjet.com/correct/#/placeOrder/index) · [资金往来](https://partner.chanjet.com/correct/#/settlement/index)

### 代理商运营演示

- 「数据运营 → 经营看板」汇总客户、直购订单、待结佣金和未关闭工单，卡片可打开对应台账。
- 「管理客户 → 客户档案」预置六家演示客户并支持搜索、新增和编辑。「续费跟进」默认显示全部已付款年度订单，可按客户、产品、订单来源和到期范围查询，显示购买日、到期日及剩余天数。扫码时填写虚构企业名称，代客下单时选择客户档案，两条路径都在付款后自动进入续费台账。
- 「资金往来」包含资金总览、交易明细、订单开票和服务费报销。在已付款订单上申请开票，或登记模拟汇款、提交服务费发票。厂商在「财务办理」登记结果。预存款、佣金和服务费分别汇总。
- 「智能工单 → 申请台账」查看预存、开票和报销的办理进度。「服务工单」可创建并关联订单。厂商在「渠道工单」提交处理结果，代理商确认关闭或补充问题后重新打开。

上述新增运营流程使用同一演示场次的数据。厂商财务办理使用模拟凭证，服务费报销使用单独的样例额度。

正式代理商可在「客户经营」使用经营看板、客户档案和续费跟进，数据由 Go API 提供。潜在客户档案仅供本组织跟进，代客下单请选择正式关联客户。厂商勾选年度授权后，新订单在登记收款时进入续费台账。需要后端迁移 `000008`。

后端应用 `000009` 后，正式代理商可从「订购结算」提交预存入账、开票和服务费报销，并从「服务支持」提交工单。正式厂商从「财务办理」设置合作代理商额度和登记办理凭证，从「渠道工单」提交处理结果。工单关闭及续问由代理商确认。正式页面的数据来自 MySQL，演示 SQLite 仅存放各场演示的样例和演示操作。

### 正式系统

正式代理商的「记拜访」已接入服务端同步，草稿仅创建成员可访问。保存并核对记录、关联真实项目后，可确认生成独立商机，团队成员能共同跟进。商机台账、伙伴、核对清单、引荐结果和待办均从正式接口读取，候选已读状态按成员保存。已有本机草稿在页面中列出，由本人逐条选择同步，原本机内容保留。三端演示步骤见 [演示脚本](../docs/demo-walkthrough.md)。

正式商机入口为 `/login/dealer?view=opportunities`，拜访入口为 `/login/dealer?view=visits`，后端需要迁移 `000004`。写入超时后会保留原请求体和编号，在当前标签刷新后可继续核对并重试。收到版本冲突时会读取最新数据，要求重新核对。正式项目详情的「记录附加商机」可直接关联项目；拜访确认后的「查看正式商机」可继续办理该记录。

商机拾遗演示位于 `/experience/dealer?view=opportunities`。从代理商项目详情也可进入「记录走访与补充需求」。试填「ERP 已定，客户还需要 IDE 接口」：先核对提取出的副需求，再选择服务类型与系统；不确定时可以留空。查看匹配依据、登记引荐、到期回访和合作结果。新增伙伴后可直接回访尚未承接的历史商机。演示数据仅供体验，介绍费是人工台账，不执行收款。[后端交班与验收脚本](../docs/opportunity-handoff.md)。

按 [Go 后端启动说明](../backend/README.md) 配置 MySQL、Redis，执行迁移并开通厂商或代理商账号，再启动 Go 服务。从相应登录入口登录，工作台以服务端返回的组织为准。Vite 默认把 `/api` 转发到 `http://127.0.0.1:8080`。Go 改用其他地址时，在运行 `npm run dev` 前设置 `PARTNERLEDGER_API_TARGET`。部署时将 `/api/*` 转发到 Go，本地静态资源直接提供，前端页面路径（含登录及演示深链接）回退到 `index.html`。

- 厂家可新增、修改产品和发布状态；经销商可分页查看已发布的产品及详情。
- 三端正式项目已接通。客户及代理商建项时选择已关联组织；代理商选真实已发布产品发起询价，厂商要求补充或标记能力缺口，代理商向客户确认后回复厂商。未关联组织会显示维护提示。服务端决定记录、字段和可办理操作。
- 项目保持原编号，在三端各自列表和详情显示。使用迁移 `000005` 时，正式项目可办理双报价、客户确认、下单、供货、整改和验收，报价、订单号和详情由服务端按角色返回。可手动刷新，页面在前台时每 20 秒更新进度。
- 提交结果不确定时保留原请求与请求键。先读取最新记录，再点击「用原请求确认结果」核对已提交的结果；当前标签刷新后仍可恢复待核对请求。版本冲突会刷新记录并提示重新核对。
- 使用迁移 `000006` 时，厂商可在产品详情维护模块、部署方式、授权范围和资料出处。代理商可解析脱敏需求或手工填写，确认后查看已发布产品及其匹配依据。选中产品和项目即可保存询价草稿。正式发给厂商前，经办人需要到项目页核对并确认提交。员工人数和授权用户数分开显示，未知授权数可留空。真实模型调用需要在后端配置 `DEEPSEEK_API_KEY`。演示端的辅助整理使用本地规则。
- 「账号与组织」显示后端返回的组织和用户，可注销当前会话。在同一浏览器标签刷新页面时，会重新核验会话。

## 双角色演示

旧版原型保留在 `/demo`，独立于三个新工作台。右上角可切换厂家与经销商，底部「重置数据」只重置旧原型。以下是旧版演示流程。

从工作台底部选择「组件库」或打开 `/ui`，可查看企业级配色、图标、卡片和交互状态。新增页面时，先参考 [UI 组件使用说明](src/ui/README.md)。

1. 经销商填写需求，保存草稿或提交询价。授权用户数待确认时可留空。厂家可要求补充资料，经销商补充后重新提交。
2. 厂家录入金额、明细和有效期后发送报价。经销商可请求修改，厂家发出新版后仍可查阅旧版。
3. 经销商确认当前有效报价，再单独生成订单。在「订单与交付」查看订单和交付节点。
4. 厂家依次更新授权、部署、迁移和交接，经销商切回后可查看进度。用页面底部的「界面状态」预览加载、空数据、无权限和失败重试。

运行 `npm test` 验证三端业务规则与接口适配，`npm run build` 验证生产构建。后续接入见 [项目接口契约](../docs/channel-contract.md)，其中列出了动作、可见字段、版本冲突及幂等规则。

首次运行浏览器回归时执行 `npx playwright install chromium`，再运行 `npm run test:e2e`。测试使用独立的前端开发端口和模拟账号，覆盖三方项目办理、翻页与返回、断线重试和同组织换号。GitHub Actions 同时运行 Go 集成测试，使用临时 MySQL 和 Redis 验证正式接口。
